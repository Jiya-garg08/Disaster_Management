About Relief Resolver

Supplies should reach the shelter that's waited longest — not just the one that asked loudest.

Relief Resolver ranks emergency requests by real urgency and packs dispatch trucks so every route stays within its safe capacity, instead of leaving that judgment call to whoever answers the phone first.

01

Verify the request

Every submission is checked against active disaster zone boundaries before it's allowed into the queue.

02

Score the urgency

Victim count and days without supply combine into a single score, so longer-waiting shelters aren't buried under raw headcount.

03

Pack the fleet

A capacity-constrained bin-packing pass fits requests onto trucks in priority order, without exceeding axle or route limits.

04

Flag the outliers

Requests with implausible victim counts are held for manual audit instead of being auto-dispatched.

How it's built

Relief Resolver is being built in two phases. Phase 1 — the version running right now — is pure HTML, CSS, and JavaScript, using the browser's local storage as its data layer so the whole system can be demonstrated without a server.

Phase 2 moves the same logic onto a full MERN stack: Express APIs running the priority queue and capacity checks server-side, MongoDB storing shelters and dispatch logs with geospatial indexing, and a React dispatcher dashboard talking to it over authenticated routes.
