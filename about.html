ABOUT RELIEF RESOLVER

When disaster strikes, help should not depend on luck.

Relief Resolver is designed to help emergency teams identify where people need shelter, food, water and essential relief — then prioritize those requests according to urgency instead of simply processing them in the order they arrive.

THE PURPOSE Move relief toward people, not paperwork.
01
Mission: connect urgent shelter needs with relief decisions.

A disaster does not wait. Neither should relief.

Our idea is simple: collect the information that matters, calculate urgency consistently, and give responders a clear queue to act on.

The system is designed around shelter, food, water and other immediate needs — because getting people somewhere safe is often the first step toward recovery.

HOW RELIEF RESOLVER WORKS

From an emergency report to a dispatch decision.

The system turns scattered emergency information into a structured priority queue for responders.

01 / INTAKE
📍

Capture the location

A shelter can select its location on the map or use the device's current location so responders know where help is needed.

02 / NEED
🏠

Understand the need

The request records vulnerable people, days without adequate support, and whether shelter, food, water, medicine or relief kits are required.

03 / PRIORITY
⚡

Calculate urgency

Victim count and waiting time are combined into an urgency score so requests can be compared consistently.

04 / DISPATCH
🚚

Coordinate relief

The Control Room can use the priority queue to decide which requests should be handled first and how relief capacity should be allocated.

HOW IT'S BUILT

Simple now. Scalable later.

Phase 1 runs entirely in the browser using HTML, CSS and JavaScript. Local storage provides the temporary data layer, while the browser's geolocation capability helps capture a request location.

The planned Phase 2 architecture moves the priority and dispatch logic server-side, with persistent storage and a dedicated dispatcher interface.

HTML CSS JavaScript Leaflet localStorage Geolocation API Node.js — Planned Express — Planned MongoDB — Planned React — Planned
Technology should support the people doing the work. The interface is built to make urgent decisions easier to see, compare and act on.
